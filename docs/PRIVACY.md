# QuoteLock privacy design note

**Scope.** A local synthetic demonstration, designed to support DPDP Act 2023 / DPDP Rules 2025 obligations. This is not a certification or legal opinion. Rules2025 have phased commencement: Gazette G.S.R.846(E),13Nov2025, Rule1 starts core Rules3,5–16,22–23 after18months (approximatelyMay2027). Applicability and retention need legal review before real use. [Official Gazette, accessed8Nov2026](https://www.meity.gov.in/static/uploads/2025/11/53450e6e5dc0bfa85ebd78686cadad39.pdf).

**Purpose, choice and minimisation.** Explain evidence validation/order continuity in the selected Hindi/English interface before consent. The API rejects evidence processing without current consent; withdrawal stops new processing, removes transient evidence authority and invalidates acceptance. Submitted receipts are not indiscriminately erased on withdrawal: legal retention, rights and deletion handling require a production policy. Collect structured business facts/budget and only necessary evidence. Quote persistence stores a business-identifier hash, not the raw registration identifier; hashes can remain personal/linkable data and need access controls too.

**AI boundary.** Only allowlisted, redacted non-commercial intent reaches the rules-based adapter. Identifiers, amounts, contacts, catalogue, quote cards, budget and order writes remain outside it. Unknown text blocks the call. Generated Hindi/English/Hinglish trials:420,0 observed payload leaks,126 blocked. This establishes behavior on that test distribution, not safety of an untested live model. Candidate slots are validated by deterministic rules; the adapter cannot approve prices or orders.

**Evidence and access.** Uploaded files and field receipts use authenticated Fernet encryption in the SQLite vault. Processing uses a temporary local image that is removed after OCR; transient OCR/identity data remain process-local. The key exists only in process memory: no durable key management, secure recovery or production key rotation. Queue responses use demo-role filters and opaque inquiry IDs, not authenticated identities or authorization. Source synthetic fixtures and evaluation/OCR reports remain developer-local plaintext and are not served as static files. Access to the machine is therefore in scope; this is not ready to host real documents. Logs/queue outputs avoid raw identity values; no credentials or external identity API call exists.

**Retention by class — draft assumptions.** Submitted raw uploads365days; extracted decision receipts365days; masked audit logs365days; accepted quote/hash records365days; abandoned/unsubmitted uploads1day. `Vault.purge_expired()` deletes expired encrypted evidence rows when called; scheduling, database backup expiry and archival quote/log deletion are not production mechanisms yet. Immutable quote records intentionally prevent ordinary update/delete; production retention requires a separately controlled archival/deletion path. Rule8(3)'s future minimum-record provision and other applicable duties need counsel review. Do not claim a complete deletion system.

**Human review and incident response.** Blur, unreadable/checksum/exact-lookup, legal-name, stale-address or authority failures create owned holds; review cannot override a failed rule. A clear packet alone cannot authorise an identity-free quote: final acceptance/lock require quote-bound business identity. No-GST previews remain pending alternative evidence. Udyam date/activity differences are explicit advisory flags, not erased. Current automatic OCR:4 core-clear/8 held; one extra false hold vs team labels. Before real deployment, appoint a grievance/incident owner, authenticate roles, manage encryption keys and integrate rights handling. The draft response disables new locks, restricts access, preserves masked evidence and investigates with the accountable owner; follow notification duties applicable at that time. The helper returns this plan; no external incident-reporting system or automatic breach detector is claimed.
